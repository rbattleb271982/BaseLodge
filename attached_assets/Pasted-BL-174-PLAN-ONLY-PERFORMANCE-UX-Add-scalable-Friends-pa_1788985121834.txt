--------------------------------------------------
PRODUCT DIRECTION TO VALIDATE
--------------------------------------------------

The intended BL-174 UX direction is:

1. Friends should scale beyond the current all-at-once loading approach.
2. Prefer infinite scroll / load-more-on-scroll rather than numbered pagination.
3. Search must be server-side across the entire friend list, not only the subset already loaded in the browser.
4. Ordering must be stable and deterministic so pagination does not create duplicates, omissions, or reshuffling.
5. The visible Friends experience should remain visually consistent with the current UI except for minimal loading / end-of-list states.
6. Do not broaden this into friend recommendations, ranking, suggestions, social intelligence, or unrelated Friends redesign.
7. Preserve all existing privacy, authorization, friendship-state, blocking, and visibility rules.

Do not assume the above implementation shape is automatically correct.

Inspect the existing code and either:
- confirm this is the safest architecture, or
- recommend a materially better implementation with clear reasoning.

Do not implement anything.
