## Approved contract

Use:

BASELODGE_MIGRATION_TARGET

Allowed values only:

- replit
- supabase-development
- supabase-production

Target URL mapping:

- replit
  - DATABASE_URL
  - DATABASE_URL is permitted ONLY after explicit target selection of `replit`

- supabase-development
  - BASELODGE_DEVELOPMENT_DATABASE_URL

- supabase-production
  - BASELODGE_PRODUCTION_DATABASE_URL

Do not allow:
- BASELODGE_MIGRATION_DATABASE_URL as a generic migration override
- DATABASE_URL to authorize either Supabase environment
- SUPABASE_DATABASE_URL to authorize migrations
- application fallback behavior to implicitly select a migration database

## Identity contract

Each target must have a separately configured expected identity hash.

Use the existing credential-free database identity machinery in runtime_config.py where possible rather than inventing a second parser.

The three expected identities must be independently configured.

The verification order must fail closed:

1. Require BASELODGE_MIGRATION_MODE=1 where migration machinery requires it.
2. Require BASELODGE_MIGRATION_TARGET.
3. Validate target is exactly one of the three allowed values.
4. Resolve only the URL source permitted for that target.
5. Reject missing URL.
6. Parse URL safely without exposing credentials.
7. Compute normalized credential-free database identity.
8. Verify database class is compatible with selected target.
9. Compare computed identity hash with the separately configured expected hash.
10. For supabase-production only, require:
   BASELODGE_CONFIRM_PRODUCTION_MIGRATION=1
11. Only after all checks pass may Alembic initialize offline configuration, create an engine, or connect.

Do not permit hostname-only matching for Supabase.

Supabase Development and Production may share a pooler hostname, so the protected project/database identity must distinguish them.
