BASELODGE — VERIFY OUTGOING PENDING FRIEND REQUEST UI

We completed the friend-request lifecycle investigation.

The investigation found that the CURRENT codebase is already intended to support the desired behavior:

Charles sends Eric a friend request from Suggested Friends
→ Eric remains visible in Charles's Suggested Friends
→ Eric's row changes from "Connect" to actionable "Requested"
→ Charles can use that state to withdraw the request
→ after withdrawal the row displays "Request withdrawn" during the 24-hour cooldown.

However, this does NOT match the actual UI behavior we observed.

Observed behavior:

After Charles sent Eric a friend request:

1. Eric did not appear in Charles's Friends list.
   - This is expected because they are not reciprocal friends yet.

2. Eric ALSO did not appear in Charles's Suggested Friends tab.
   - This is NOT expected according to the current implementation.

3. Charles therefore had no visible "Requested" state and no way from this UI to withdraw the pending invitation.

We now need to determine why the live/runtime behavior does not match the current code.

DO NOT redesign the friend system.

The desired behavior already exists conceptually. Debug the discrepancy.
