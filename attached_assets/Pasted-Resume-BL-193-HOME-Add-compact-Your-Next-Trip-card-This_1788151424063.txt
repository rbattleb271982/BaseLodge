APPROVED PRODUCT DECISION

“Friends going” means confirmed direct friends who are actually going on the selected next trip.

Count:
- direct friends of the current user whose trip participation status is GOING
- the trip owner, if:
  - the owner is a direct friend of the current user
  - the owner is not the current user

Do NOT count:
- the current user
- INTERESTED participants
- pending participants/invites
- declined participants
- removed participants
- non-friends
- duplicate friend records

A friend must count at most once.

The trip does NOT need to be public.
Use the existing authorized next-trip population and existing trip visibility behavior.
Do not import Ideas/Happening public-trip semantics.

APPROVED QUERY DECISION

One explicit, bounded query for the single authoritative `next_trip` is approved.

Requirements:
- query only for the selected `next_trip.id`
- do not access `next_trip.participants` in a way that triggers implicit lazy loading
- do not load the full roster if a direct aggregate/count query can provide the answer
- avoid N+1 behavior
- do not query Friends separately if the existing direct-friend IDs already loaded by Home can safely constrain the query
- preserve existing direct-friend semantics

After resolving the count, add it to the BL-187 summary contract as:

home_summary["next_trip"]["friends_going_count"]

The template must consume the resolved count and must not issue queries.

This is an approved, narrow extension of BL-187’s next_trip contract for BL-193.
