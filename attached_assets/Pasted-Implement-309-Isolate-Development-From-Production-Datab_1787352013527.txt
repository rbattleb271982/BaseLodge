1. Add explicit runtime configuration
Add a small, side-effect-free configuration layer using:
BASELODGE_RUNTIME_ENV
Supported values:
development
test
production
Invalid or missing values must fail closed.
Do not use FLASK_ENV or REPLIT_ENVIRONMENT as the source of truth for database selection.
2. Environment-specific database configuration
Support:
BASELODGE_DEVELOPMENT_DATABASE_URL
BASELODGE_TEST_DATABASE_URL
BASELODGE_PRODUCTION_DATABASE_URL
BASELODGE_MIGRATION_DATABASE_URL
Development
When BASELODGE_RUNTIME_ENV=development:
require BASELODGE_DEVELOPMENT_DATABASE_URL
never fall back to production
never fall back to SUPABASE_DATABASE_URL
fail closed when missing
reject the known production database identity before SQLAlchemy creates an engine
Test
When BASELODGE_RUNTIME_ENV=test:
require an isolated test DB
never inherit production credentials
never fall back to shared Supabase configuration
reject the known production database identity before engine creation
Production
When BASELODGE_RUNTIME_ENV=production:
require explicit production DB configuration
do not permit development/test configuration to become the active connection
If current production still requires a temporary SUPABASE_DATABASE_URL compatibility path, keep it narrowly production-only and explicitly documented.
It must never operate in development or test.
Migration
Migration tooling must use:
BASELODGE_MIGRATION_DATABASE_URL
independently of normal Flask app startup.
3. Production database identity guard

host
port

password
credentials
complete connection URL

There must be no silent cross-environment fallback.
