# 2. SHARED RESORT SELECTOR

Create one reusable template partial:

templates/partials/resort_selector.html

Both pages must use this shared selector rather than duplicating the implementation.

Mountains Visited should configure it as:

rs_mode = 'visited'
rs_selected_ids = selected_resort_ids
rs_limit = None

Wishlist should configure it as:

rs_mode = 'wishlist'
rs_selected_ids = wish_list_ids
rs_limit = 15

The shared partial should use rs_mode to determine:

- correct AJAX add endpoint
- correct AJAX remove endpoint
- appropriate checkbox/ARIA labels
- visited vs wishlist count language
- wishlist limit behavior

Do NOT merge the underlying visited and wishlist data.

They remain completely separate states.

---

# 3. SEARCH

At the top of the selector, provide:

Search mountains

Use the existing canonical:

.bl-search-input

Search must operate across the entire resort dataset, not only the currently expanded accordion.

Search should match:

- resort name
- state name
- state code
- country name
- country code

Search results should provide enough geographic context to distinguish resorts with similar names.

For example:

Mammoth Mountain · California

Tapping a search result should immediately add the resort using the existing AJAX endpoint.

The corresponding resort checkbox in the hierarchy must immediately reflect the new state.

Do not create a new manually maintained resort list.

Use the existing resort data already supplied to the templates.

---

# 4. HIERARCHICAL ACCORDION

Below the search field, display the full active, non-region resort database in the hierarchy:

Country
→ State/Province/Region
→ Resort

Countries are collapsible.

States/provinces/regions are collapsible.

Resort rows are selectable.

## Initial expansion behavior

This is important:

- Countries containing at least one selected resort should be expanded automatically on page load.
- States/provinces/regions containing at least one selected resort should be expanded automatically on page load.
- Countries with no selected resorts should remain collapsed.
- States with no selected resorts should remain collapsed.

This allows the user to immediately see where their existing visited/wishlisted resorts are without dumping the entire resort database onto the screen.

Do NOT expand the entire database by default.

## Interaction

Tapping a country header toggles its state/province/region rows.

Tapping a state/province/region header toggles its resort rows.

Use a clear chevron/expanded indicator.

Use appropriate ARIA attributes such as aria-expanded where applicable.

---

# 5. RESORT ROWS

Each resort should be represented by a full-height tappable row.

Minimum tap target:

44px.

The row should contain:

Left:
Resort name

Right:
Checkbox/selection indicator

Tapping anywhere on the resort row should toggle the selection.

Do not require the user to hit the tiny checkbox itself.

The checkbox/selection control must remain visually clear.

Selected resorts should have a clear selected state consistent with BaseLodge's existing design language.

Do not introduce an unrelated visual style.
