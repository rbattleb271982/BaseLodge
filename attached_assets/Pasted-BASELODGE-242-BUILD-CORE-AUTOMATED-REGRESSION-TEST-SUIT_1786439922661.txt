BASELODGE — #242 BUILD CORE AUTOMATED REGRESSION TEST SUITE

Implement a focused automated regression test suite for the highest-risk BaseLodge flows we just stabilized.

This is NOT a broad unit-test-everything task.

The goal is to protect:

- authorization boundaries
- account deletion
- trip deletion
- Trip Planning
- My Setup
- inline Edit trip
- invite acceptance
- CSRF
- private trip visibility
- notification recipient rules

DO NOT:
- change product behavior
- change schema
- change notifications
- change routes merely to make tests easier
- refactor large areas of app.py
- seed production data
- run destructive tests against production data

Use isolated test data / test DB / rollback patterns appropriate for the existing project.

==================================================
1. FIRST — INSPECT EXISTING TEST INFRASTRUCTURE
==================================================

Before creating anything, inspect the repository for:

- pytest
- unittest
- conftest.py
- test fixtures
- test database configuration
- Flask test_client patterns
- environment-variable handling
- existing test dependencies

If no automated test structure exists, establish the smallest conventional setup compatible with the current Flask app.

Prefer pytest if already available or easily supported by the existing environment.

Do not introduce a large testing framework.

==================================================
2. TEST ENVIRONMENT SAFETY
==================================================

Tests must NEVER operate against the production database.

Before running any destructive test:

confirm that the test environment/database is isolated.

If the current application architecture makes that impossible:

STOP and report.

Do not run destructive automated tests against live BaseLodge data.
