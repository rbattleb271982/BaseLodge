## BLOCKER 3 — NULL-safe outgoing pagination

The investigation established:

- Invitation.created_at is nullable at the database level.
- Normal ORM creation receives a Python default.
- Development currently contains no qualifying NULL rows.
- Production was not accessed.
- NULL remains a valid persisted legacy/raw-SQL state.
- SQLite and PostgreSQL order NULL differently under bare DESC.
- Current cursor logic cannot guarantee traversal of qualifying NULL rows.

NO MIGRATION IS REQUIRED.

Implement the approved application-level nullable-keyset convention based on the existing pattern in:

services/my_trips_paging.py

### Required ordering

Define an explicit null rank equivalent to:

null_rank = CASE
    WHEN Invitation.created_at IS NULL THEN 1
    ELSE 0
END

Order outgoing requests by:

1. null_rank ASC
2. Invitation.created_at DESC
3. Invitation.id DESC

This means:

- normal timestamped requests remain newest-first
- legacy NULL rows appear after timestamped requests
- NULL ordering is identical across SQLite and PostgreSQL

### Cursor

Update the signed outgoing-request cursor contract to include null rank.

Requirements:

- bump the cursor version
- rank 0 requires a valid datetime
- rank 1 requires no datetime
- retain Invitation ID
- retain viewer binding
- retain signature/tamper protection

Reject inconsistent payloads such as:

- rank 0 + NULL timestamp
- rank 1 + non-NULL timestamp

### Continuation

Implement rank-aware keyset continuation.

For a non-null/rank-0 cursor, continuation must allow:

- remaining timestamped rows according to created_at/id
- transition into rank-1 NULL rows

For a rank-1 cursor:

- remain within rank 1
- continue by Invitation.id DESC

Do not use backend-default NULL ordering.

Do not fabricate timestamps.

Do not backfill data.

Do not create a migration.

### Required NULL pagination tests

Add focused coverage for:

- mixed timestamped and NULL qualifying rows
- more than 20 timestamped rows followed by NULL rows
- more than 20 NULL rows
- page boundary transitioning from timestamped to NULL
- multiple NULL rows ordered by ID DESC
- equal non-null timestamps ordered by ID DESC
- complete traversal count equals total_count
- no duplicate IDs across pages
- no omitted IDs across pages
- cursor rank 0 + datetime
- cursor rank 1 + no datetime
- invalid rank/timestamp combinations rejected
- viewer binding after cursor-version change
- tampered cursor rejection
- existing 0/1/20/21/41 non-null boundaries remain correct
- fixed query statement budget remains intact

Tests that require persisted NULL created_at must create it in a way that bypasses/moves past the SQLAlchemy Python default, since normal ORM construction masks created_at=None.
