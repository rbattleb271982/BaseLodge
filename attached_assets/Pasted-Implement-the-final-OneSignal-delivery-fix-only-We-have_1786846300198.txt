Implement the final OneSignal delivery fix only.
We have now proven the root cause:
OS.initialize() currently runs while OneSignal's permission state is not_determined. During initialization, the SDK reports that state to OneSignal and the iPhone subscription becomes notification_types=-30 / disabled server-side. Calling optIn() afterward cannot reliably repair it because the bad SDK state has already been reported.
Required fix
Change the initialization sequence so that:
1. OS.Notifications.requestPermission() runs BEFORE OS.initialize()
2. Wait for that permission call to complete before calling OS.initialize().
3. Only then run the existing initialization/login sequence:
requestPermission → initialize → login → subscription preference sync
Before implementing, verify from the installed onesignal-cordova-plugin v5.3.8 source/API that OS.Notifications.requestPermission() is valid before OS.initialize(). If it is not valid, STOP and report that rather than implementing an unsupported sequence.
