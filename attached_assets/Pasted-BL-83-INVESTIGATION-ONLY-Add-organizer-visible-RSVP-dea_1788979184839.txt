--------------------------------------------------
BL-83 PRODUCT CONTRACT
--------------------------------------------------

Goal:

Allow a trip organizer to optionally set an RSVP deadline for a trip.

This task is intentionally narrow.

Required behavior:

1. RSVP deadline is OPTIONAL.
2. The trip organizer can add an RSVP deadline.
3. The organizer can edit an existing RSVP deadline.
4. The organizer can remove an RSVP deadline.
5. Relevant trip participants can see the deadline.
6. The deadline must be persisted as canonical trip data.
7. Deadline writes must use appropriate trip-organizer authorization.
8. Deadline input must be safely validated.
9. Existing trips without a deadline must continue working normally.
10. Existing RSVP behavior must remain unchanged.

EXPLICITLY OUT OF SCOPE:

- automated reminders
- reminder scheduling
- push notifications
- email
- SMS
- lifecycle messaging
- organizer follow-up workflows
- participant action tracking beyond existing RSVP behavior
- Home actions
- deadline-driven recommendations
- Happening distribution
- analytics changes unless absolutely required by an existing mandatory convention
- native iOS/Android-specific work

The deadline should establish canonical state that future reminder/lifecycle features could consume, but BL-83 must NOT implement those future behaviors.
