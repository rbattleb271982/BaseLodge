6. KEYSET CURSORS
==================================================

Implement strict opaque URL-safe cursors.

Cursor payload must be sufficient to reproduce the section's complete ordering key.

At minimum encode/validate:

- section
- source rank
- null-date rank
- date value
- trip ID

Requirements:

- malformed cursor → 400
- mismatched section cursor → 400
- unsupported cursor shape/version → 400
- cursor filtering happens only inside the fully authorized query
- cursor values never grant access
- client cannot raise page size

Do not silently convert invalid cursors into an empty successful page.

==================================================

Server page size:

20

For each section request:

- fetch at most 21 lightweight authorized candidate rows
- first 20 are the page
- 21st determines has_more
- do not hydrate/render the lookahead row

Return next_cursor only when another page exists.

Phase 2:
Hydrate only the first 20 page trips.

Include required related data such as Resort using page-scoped eager/batch loading.

Do not hydrate the entire eligible trip universe.
