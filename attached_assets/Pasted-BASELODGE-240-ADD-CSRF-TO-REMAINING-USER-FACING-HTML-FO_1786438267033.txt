BASELODGE — #240 ADD CSRF TO REMAINING USER-FACING HTML FORM MUTATIONS

Implement ONLY coordinated CSRF protection for the remaining user-facing HTML form routes listed below.

Audit #234 confirmed these routes are browser/session-authenticated mutations that are not yet fully protected.

For each true HTML form route, protection requires BOTH:

1. <input type="hidden" name="csrf_token" value="{{ csrf_token() }}">
2. validate_csrf_request() in the receiving POST handler

DO NOT:
- modify global CSRF infrastructure
- modify analytics_head.html
- modify the global fetch wrapper
- change authentication/session behavior
- change permissions
- change business logic
- change notifications
- change schema
- redesign any page
- touch admin routes
- touch routes already fixed in #236–#239

==================================================
1. ROUTES IN SCOPE
==================================================

Audit and protect these remaining user-facing mutation routes:

POST /add-open-dates

POST /select-pass

POST /edit_profile

POST /settings/profile

POST /onboarding

POST /location-setup

POST /feedback

POST /mountains-visited

POST /group-trip/<id>/transportation

If exact route names or parameters differ, use the current definitions.

IMPORTANT:

Some may be combined GET+POST handlers.

Only validate CSRF on POST.

Do not cause normal GET page loads to return 403.

==================================================
2. VERIFY CURRENT CALLERS FIRST
==================================================

For each route:

Identify the exact template/form or fetch caller.

Confirm:

- method
- action
- whether csrf_token already exists
- whether backend already validates
- whether submission is HTML form or fetch

If a route is actually fetch-based:
do not add a hidden form token unnecessarily.

If the fetch wrapper already supplies X-CSRF-Token:
backend validation only is sufficient.

If a route is already fully protected:
leave it unchanged and report it.

==================================================
3. TRUE HTML FORM ROUTES
==================================================

For each HTML POST form missing CSRF add:

<input type="hidden" name="csrf_token" value="{{ csrf_token() }}">

directly inside the relevant <form>.

Do not change:
- visible fields
- copy
- buttons
- layout
- form action
- method

==================================================
4. BACKEND VALIDATION
==================================================

For each in-scope mutation handler missing protection add:

validate_csrf_request()

before:

- request.form/request.json parsing
- DB mutation
- session mutation tied to the POST
- analytics triggered by successful submission
- commit

For combined GET/POST handlers:

if request.method == "POST":
    validate_csrf_request()

Do not run CSRF validation on GET.
