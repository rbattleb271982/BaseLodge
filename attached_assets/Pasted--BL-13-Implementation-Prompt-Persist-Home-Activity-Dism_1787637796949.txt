# BL-13 Implementation Prompt — Persist Home Activity Dismissals

Implement **BL-13: Home Activity Empty States** based on the completed investigation.

## Objective

Fix the Home activity dismissal persistence bug while preserving the existing empty-state and immediate UI reconciliation behavior.

The investigation confirmed that most BL-13 behavior already works correctly:

* Empty Happening sections do not render.
* Empty Ideas sections do not render.
* No stale section spacing remains.
* If both sections are empty, the existing single fallback appears.
* Dismissing the final card in a section immediately removes the heading/container.
* If both sections become empty after dismissal, the fallback appears immediately.

The actual defect is:

> Home activity dismissals are removed optimistically in the browser, but the POST to `/dismiss-insight-card` does not include a valid CSRF token, so the dismissal may not persist. After refresh, the card can return.

Fix that defect without redesigning the existing Home activity system.

## Required implementation

### 1. Add CSRF to Home dismissal requests

Update the existing Home dismissal flow so `dismissInsightCard(...)` sends the valid session CSRF token with the request to:

`/dismiss-insight-card`

Use the application's existing CSRF mechanism and patterns.

Do not:

* weaken CSRF protection;
* exempt the route from CSRF;
* create a second dismissal endpoint;
* introduce a new authentication mechanism.

Prefer exposing the existing CSRF token to the Home JavaScript and including it in the existing `FormData`.

### 2. Preserve existing optimistic behavior

Keep the current UX:

1. User dismisses a Happening or Ideas card.
2. Card fades/removes immediately.
3. If it was the final card in the section:

   * remove the section wrapper;
   * remove the heading;
   * collapse section spacing.
4. If both Happening and Ideas are now empty:

   * reveal the existing `home-activity-fallback`.

Do not redesign this interaction.

### 3. Preserve existing server-side filtering

The existing persisted `DismissedInsightCard` logic is already correct.

Do not change the underlying data model or filtering behavior unless a failing test proves a server-side defect.

The expected behavior after this fix is:

**Dismiss card → persistence succeeds → reload Home → dismissed card remains absent.**

### 4. Preserve existing fallback

Reuse the current fallback exactly as-is.

Do not introduce new copy or another empty-state component.

Current intended fallback behavior:

* With availability:

  * show existing availability ranges;
  * retain **Edit availability**.
* Without availability:

  * retain **Add dates to unlock trip ideas**;
  * retain **Add availability**.

### 5. Do not expand scope

Keep these existing behaviors out of BL-13:

* The Ideas pill may still target a missing Ideas section when there are no Ideas.
* No rollback/error UI is required if a network request fails after optimistic removal.
* Do not redesign Happening.
* Do not redesign Ideas.
* Do not change Home content ordering.
* Do not change Home recommendations.
* Do not change gear, Friends' Passes, requests, availability, or unrelated Home surfaces.

If you identify a serious regression risk outside scope, report it rather than expanding the task.
