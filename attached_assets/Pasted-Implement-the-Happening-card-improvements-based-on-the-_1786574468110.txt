Implement the Happening card improvements based on the completed investigation.

The goal is to improve readability and make the cards slightly more compact while preserving the existing BaseLodge visual style.

## Target layout

Change the current structure from:

**Taylor Mercer - Planning Shiga Ko...**
Added this week

to:

**Taylor Mercer** — Planning
Shiga Kogen · Added this week

For example:

**Olu Osinowo** — Planning
Whistler Blackcomb · Recently updated

The resort is important information and should **never be truncated just to preserve recency text**.

If the resort + recency combination cannot fit on one line, allow the recency text to wrap naturally below it:

**Mackenzie Robertson** — Planning
Les Arcs / Peisey-Vallandry
Recently updated

Do not force every card to three lines. Most cards should remain two lines.

## 1. Separate the backend data

In the existing Happening signal construction in `app.py`, expose the activity verb and mountain separately instead of requiring the template to parse `action_line`.

Preserve the existing status behavior:

* `going` → `Going to`
* `confirmed` / `booked` → `Heading to`
* `planning`, NULL, or other → `Planning`
* No mountain → `Trip upcoming`

Keep `action_line` if anything else currently relies on it. Do not introduce a regression elsewhere.

## 2. Update the Happening card markup

In:

`templates/partials/home/_section_happening.html`

Render the content hierarchy as:

### Line 1

**Friend Name** — Activity

Name should remain semibold/bold.

Activity should be regular weight.

### Line 2

Resort · Recency

The resort should be visually stronger than recency.

The recency text should remain muted.

Do not truncate the resort.

Structure the markup/CSS so that if the combined resort + recency content does not fit, **recency wraps below while the full resort remains visible**.

Do not use JavaScript to calculate text width.

For the no-mountain case, preserve the existing `Trip upcoming` behavior cleanly.

## 3. Make the cards slightly more compact

Apply these adjustments:

* Main/name/activity font: `17px → 16px`
* Resort: `15px`
* Recency: `14px → 13px`
* Top/bottom card padding: `12px → 10px`
* Left padding: `20px → 16px`
* Gap between Happening cards: `10px → 8px`

**Keep the existing 16px card border radius.**

Do not make the cards feel cramped and do not alter the overall BaseLodge visual language.

## 4. Dismiss ×

Move the visible × toward the upper-right corner and make it slightly less visually prominent.

Target visual treatment:

* Approximately 13px visible ×
* Lower resting opacity around `0.38`
* Higher opacity on active interaction
* Top-right placement appropriate for the new two-line layout

However, **do not reduce the actual interactive tap target to ~29×29px**.

Keep a generous invisible/padded hit area appropriate for mobile while making only the visible × smaller.

Make sure the text still has sufficient right-side clearance so it cannot render underneath the dismiss control.

Preserve existing dismissal behavior and accessibility.

## 5. Wrapping behavior

This is important.

Do NOT restore the current:

`white-space: nowrap`
`overflow: hidden`
`text-overflow: ellipsis`

behavior for the resort.

The desired priority is:

1. Show full friend name where reasonably possible
2. Show activity
3. Always preserve the full resort name
4. Keep recency inline when space permits
5. Allow recency to wrap to the next line when necessary

Avoid unnecessary three-line cards for normal content.

## 6. Scope

Do not change:

* Happening feed selection logic
* Five-card render cap
* Dismissal endpoint
* Friend-trip query
* Recency calculations
* Meaning of Planning / Going to / Heading to
* Other home-page sections
* Desktop/tablet styling unless necessary to prevent a regression
