#218 - Correct Ski Pass Resort Mappings

## Objective

Correct the confirmed resort-to-ski-pass mapping errors identified during the Ski Pass Resort Mapping Audit.

The immediate known issue is that Valle Nevado is currently displayed as `Other` instead of `Ikon`.

This is an implementation task.

Make only the smallest safe code and data changes needed to ensure that BaseLodge displays accurate ski-pass associations for Valle Nevado and every other resort confirmed as incorrect by the audit.

Do not redesign the ski-pass architecture.

Do not add blackout-date logic.

Do not create pass-tier functionality.

Do not change user pass preferences.

---

# Required Approach

Before changing anything:

1. Complete and document the live-data verification described below.
2. Confirm the exact source of every incorrect mapping.
3. Correct all confirmed mapping errors in one controlled update.
4. Ensure the canonical data source, database records, and displayed results remain aligned.

Do not rely only on CSV files without verifying the live database and current display logic.

---

# 1. Verify the Current Mapping Architecture

Confirm the current behavior of:

* `ResortPass`
* `Resort.pass_brands_json`
* legacy `Resort.pass_brands`
* `_RESORT_PASS_OVERRIDES`
* `get_all_active_resorts_map()`
* resort import scripts
* resort pass backfill scripts
* admin pass-management tools

Document the exact priority order used to determine which passes are displayed.

Confirm which source is intended to be canonical.

Do not create a new storage system.

# 2. Verify Valle Nevado

Query the live database for Valle Nevado and report:

* Resort ID
* exact resort name
* slug
* active status
* `pass_brands`
* `pass_brands_json`
* all associated `ResortPass` rows
* the final pass value returned by `get_all_active_resorts_map()`

Confirm whether the existing incorrect display is caused by:

* a missing `ResortPass` row
* an incorrect `ResortPass` row
* stale import data
* a name or slug mismatch
* a legacy fallback
* an override
* another issue

Valle Nevado must display as an Ikon destination after the correction.

Do not represent access as unlimited or guaranteed. BaseLodge should only show the pass brand association currently supported by the existing product.

# 4. Correct the Canonical Database Records

Correct all confirmed pass mappings in the canonical database structure.

Requirements:

* Add missing `ResortPass` rows.
* Remove incorrect `ResortPass` rows.
* Preserve valid existing pass associations.
* Support resorts belonging to more than one pass.
* Avoid duplicate rows.
* Do not remove valid secondary passes.
* Do not modify unrelated resort data.
* Do not modify user pass selections.

Use the project’s normal data-migration or startup-migration convention.

The correction must be:

* idempotent
* safe across repeated deployments
* transactional where appropriate
* logged clearly
* limited to explicitly identified resort records

Prefer stable identifiers such as resort IDs or slugs rather than loose display-name matching.

If a resort cannot be safely located by a stable identifier, do not update it automatically.
