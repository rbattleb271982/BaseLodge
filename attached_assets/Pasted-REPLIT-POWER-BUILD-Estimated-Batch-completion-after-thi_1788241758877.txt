TASK: BL-175 — Lazy-load Friends suggestions

Use Task #415 PLAN as the implementation contract.

GOAL

Remove full Suggested Friends hydration from the initial Friends page response.

Keep only a cheap authorized suggestion count for the existing badge, then load Suggested Friends on demand through bounded, server-rendered pagination.

IMPLEMENT ONLY THIS SCOPE.

1. BOUND SUGGESTION RETRIEVAL

Add a recipient-authorized suggestion paging service that:

- groups active suggestion rows by suggested person BEFORE applying the page limit
- preserves current suggestion ordering
- preserves current attribution behavior
- preserves existing Accept vs Connect state
- excludes dismissed or expired suggestions
- uses signed, viewer-scoped, versioned, typed cursors
- never loads the full suggestion universe to create a page

Use a small bounded page size consistent with the current Friends UX.

2. CHEAP INITIAL BADGE COUNT

On the default Friends render:

- do not hydrate suggestion cards
- do not hydrate suggested users/suggesters/inbound request state for cards
- compute only the smallest authorized distinct suggested-person count required for the existing badge

Keep incoming friend requests synchronous and unchanged.

Keep the primary Friends directory unchanged.

3. CANONICAL SUGGESTION ENDPOINT

Add one authenticated endpoint for bounded suggestion pages.

Requirements:

- authenticated viewer is the recipient
- active/non-dismissed/non-expired rules are rechecked on every request
- cursor viewer binding and tamper protection
- server-rendered canonical suggestion fragment
- existing card actions/copy/preview behavior preserved
- no client-side reconstruction of suggestion state

4. LOAD SUGGESTIONS ON DEMAND

In Friends:

- default Friends tab must not request suggestion-card data
- first suggestion page loads when Suggested Friends becomes visible
- `/friends?tab=suggested` should trigger the same first-page load after the primary shell renders
- subsequent pages use bounded Load More behavior

Preserve:

- active tab
- directory filters/search
- already loaded directory rows
- directory cursor
- focus
- scroll position
- pending controls
- suggestion preview behavior

Do not create a new refresh engine.

Use the existing Friends page-local paging pattern and remain compatible with BL-173 targeted refresh regions.

5. MUTATION COMPATIBILITY

Existing suggestion actions must continue to work unchanged:

- Connect

- dismiss
- preview behavior
- attribution behavior
- notification behavior
