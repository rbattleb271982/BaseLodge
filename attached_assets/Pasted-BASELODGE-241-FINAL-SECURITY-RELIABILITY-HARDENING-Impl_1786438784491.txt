==================================================
PART A — /skip-pass-prompt GET → POST
==================================================

Current issue:

GET /skip-pass-prompt

mutates:

session["pass_prompt_skipped"] = True

Audit #234 classified this as a low-risk state-changing GET.

Convert this action to POST.

==================================================
A1. TRACE ALL CALLERS
==================================================

Search the entire codebase for callers of:

/skip-pass-prompt
url_for('skip_pass_prompt')
skip_pass_prompt

Identify:
- templates
- links
- JS
- native/WebView callers
- redirects

Do not change anything until all callers are known.

==================================================
A2. CONVERT TO POST
==================================================

Change the mutation endpoint so the state-changing action occurs through POST.

The new POST must:

- retain the existing login/auth behavior
- call validate_csrf_request()
- set the exact same session value
- preserve the existing destination/response behavior

Do not introduce any DB write.

==================================================
A3. UPDATE CALLER
==================================================

If current UI uses an <a href>:

replace it with either:

A. a tiny POST form with hidden csrf_token

or

B. existing window.fetch POST behavior

Choose whichever best matches the current UI without changing its appearance.

If using fetch:
the global fetch wrapper already injects X-CSRF-Token.

If using a form:
include:

<input type="hidden" name="csrf_token" value="{{ csrf_token() }}">

The visible interaction must remain unchanged.

==================================================
A4. VALIDATE
==================================================

Confirm:

POST + valid CSRF
→ existing skip behavior works

POST + missing CSRF
→ 403

POST + invalid CSRF
→ 403

GET /skip-pass-prompt
→ does NOT mutate session state

Prefer either:
- 405 Method Not Allowed
or
- a harmless redirect

depending on the cleanest current route structure.

==================================================

Audit #228 identified:

currently scans all:

Activity rows in Python and inspects:

extra_data["trip_ids"]

This is functionally correct after #230, but inefficient as Activity volume grows.

Improve this helper without changing its behavior.

==================================================
C1. INSPECT DATABASE TYPE
==================================================

Before changing the query, inspect:

Activity.extra_data

Determine the actual database type:

- JSON
- JSONB
- text
- other

Use an approach supported by the actual PostgreSQL/SQLAlchemy column type.

Do not assume JSONB containment if it is not JSONB.

==================================================
C2. FILTER IN DATABASE WHERE SAFE
==================================================

Goal:

avoid loading every overlap Activity into Python.

Filter first on:

activity type == FRIEND_TRIP_OVERLAPS_AVAILABILITY

and then, where supported safely, filter for records whose:

extra_data.trip_ids

contains the target trip ID.

Important:

trip_ids may contain integers or strings depending on historical data.

Inspect real data first.

The optimized helper must remove every row the old helper would have removed.

==================================================
C3. FALLBACK IF DB QUERY IS UNSAFE
==================================================

If the schema/database representation makes a reliable containment query risky:

do NOT force a fragile optimization.

Instead improve the query as far as safely possible and report why full DB containment was not used.

Correctness is more important than optimization.
