APPROVED ACTION 1 — INTERESTED GUEST

- selected Next Trip exists
- current user is not owner
- current user is an active participant
- current participant status is INTERESTED

Action:
- key: stable canonical value
- type: stable canonical value
- label: `Review RSVP`
- destination: existing Trip Detail route for selected trip with anchor `#td-self-rsvp`
- fixed priority

Pending invitees remain outside Next Trip and receive no action here.

APPROVED ACTION 2 — OWNER PENDING JOIN REQUESTS

Eligibility:
- selected Next Trip exists
- current user owns selected trip
- selected trip has at least one pending join request

Action:
- key: stable canonical value
- type: stable canonical value
- label: `Review join requests`
- destination: existing Trip Detail route for selected trip with anchor `#td-join-requests`
- fixed priority

Use at most one additional bounded existence query for the selected owner trip.

Do not load participant/request collections lazily.
Do not introduce N+1 behavior.
Do not retrieve unnecessary participant names or roster details.
