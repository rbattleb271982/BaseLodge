--------------------------------------------------
5. NOTES AUTHORIZATION
--------------------------------------------------

Core requirement:

Only the trip owner can create, edit, or clear the trip notes.

Accepted participants may VIEW the notes.

Non-owner participants must not see an editable textarea or Save button.

Preserve the existing trip access-control rules for who can access trip_detail at all.

If a non-owner participant expands Notes:
- show the saved note as read-only text
- if there are no notes, either hide the Notes row for them or show a non-editable empty state, whichever best matches the existing architecture

Do not expose trip notes to someone who cannot otherwise access the trip.

--------------------------------------------------
6. NOTES SAVE ENDPOINT
--------------------------------------------------

Implement the smallest endpoint that fits the current architecture.

Preferred pattern:

POST /api/trip/<id>/notes

or an equivalent naming pattern consistent with the existing endpoints:

/api/trip/<id>/accommodation
/api/trip/<id>/equipment-override
/api/trip/<id>/participant/settings

Requirements:

- login required
- load trip by ID
- owner-only write authorization
- trim surrounding whitespace
- enforce max 500 characters server-side
- empty string should clear the notes to NULL or empty consistently
- return JSON success/error
- use CSRF protections/patterns already used by nearby AJAX endpoints
- do not create a generic “update trip” endpoint
- do not modify the legacy /api/trip/<id>/edit route
