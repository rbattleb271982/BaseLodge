BL-79 — Preserve connection formed/removed history

PLAN / INVESTIGATION ONLY.

Do not modify code, tests, migrations, schema, database state, configuration, dependencies, or data.
Do not commit anything.
Do not access or modify Production.
Do not run migrations against Development or Production.

GOAL

Quietly preserve when a BaseLodge connection existed so historical trips and future intelligence can later be interpreted correctly.

NOTION REQUIREMENTS

- Preserve connection-created and connection-removed events internally.
- Never create a public Former Friends concept.
- Removed connections must not regain access to current/private information because historical relationship data exists.
- Respect account deletion/privacy requirements.

USER DATA SAFETY GATE

This changes persisted social-graph history.

Before implementation we need:

- explicit access-control review;
- migration/backfill decision;
- rollback strategy;
- duplicate-event/idempotency strategy;
- privacy/account deletion behavior;
- verification before any intelligence feature consumes the data.
