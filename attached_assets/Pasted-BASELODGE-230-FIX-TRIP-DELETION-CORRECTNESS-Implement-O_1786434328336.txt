==================================================
BACKGROUND
==================================================

Audit #228 identified divergent trip-deletion behavior.

There are at least two trip deletion paths:

1. delete_trip_form()
2. delete_trip() API route

The form path currently performs more complete cleanup.

The API path is missing cleanup for at least:

- TripInviteToken
- Invitation rows related to the trip

This can cause:

- FK IntegrityError when deleting trips with invite tokens
- stale/orphan Invitation rows
- inconsistent behavior depending on which delete path is used

The audit also found:

delete_availability_overlap_activities_for_trip()

exists but is not called by either trip deletion path.

Deleted trips can therefore remain referenced in FRIEND_TRIP_OVERLAPS activity data.

Fix these issues while preserving existing product behavior.

9. TRANSACTION SAFETY
==================================================

The API delete path was also found to lack robust try/except rollback handling.

Make both deletion paths transaction-safe.

Requirements:

- all DB cleanup and trip deletion occur before commit
- one logical deletion transaction
- rollback on any exception
- no partially-deleted trip state
- notifications only after successful commit

Do not send TRIP_CANCELLED if deletion fails.

Preserve existing user-facing error response style for each route:
- HTML/form path remains HTML-compatible
- API path remains JSON-compatible
