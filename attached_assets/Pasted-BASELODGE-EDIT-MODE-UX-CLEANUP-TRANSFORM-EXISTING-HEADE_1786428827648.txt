BASELODGE — EDIT MODE UX CLEANUP
TRANSFORM EXISTING HEADER CONTROLS IN PLACE

Make a tightly scoped UX refinement to the owner Edit mode on trip_detail.

The underlying single-page edit architecture is already correct.

Do NOT change:
- ownership model
- permissions
- routes
- models
- notifications
- My Setup architecture
- Trip Planning
- participant behavior
- legacy Edit page fallback

GOAL

When the owner taps Edit, the page should feel like the EXISTING trip page becoming editable.

It should NOT feel like a second edit form was inserted underneath the existing trip summary.

The current Edit mode duplicates Visibility and Status:
- read-only badges remain visible
- separate VISIBILITY and STATUS segmented controls appear below them

Remove that duplication.

9. REMOVE VISIBLE “SAVE NOTE” BUTTON
==================================================

Remove the visible:

Save note

button from Edit mode.

Reason:

Done already checks for unsaved private-note changes and auto-saves before exiting.

There should be one clear completion action:

Done

Behavior must remain:

- If note unchanged → Done exits immediately
- If note changed → Done saves note first
- If save succeeds → exit edit mode
- If save fails → stay in edit mode and show error
- Note must never be silently lost

Do not remove the underlying saveNote() logic if Done depends on it.

Only remove the extra visible Save note action.
