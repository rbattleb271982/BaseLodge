--------------------------------------------------
BL-164 GOAL
--------------------------------------------------

The current BaseLodge request lifecycle appears to perform diagnostic/database work during the first real user request after process startup.

BL-164 should remove expensive startup-only diagnostics from user request handling while preserving useful operational visibility.

We need to determine exactly what currently happens, why it happens, how expensive it is, and the smallest safe architecture for moving it elsewhere.

Do NOT implement the recommendation yet.
