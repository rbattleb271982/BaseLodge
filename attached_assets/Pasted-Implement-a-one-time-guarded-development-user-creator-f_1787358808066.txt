Implement a one-time guarded development-user creator for the isolated BaseLodge development database.
This is a development-only implementation task.
Do not touch production.
Do not use the normal signup UI.
Do not resume BL-77.
Goal
Create a standalone safe tool that can create exactly one usable BaseLodge development account without:
importing app.py
importing Flask
triggering startup mutators
sending analytics
sending email
invoking OneSignal
creating push tokens
copying production user data
copying production password hashes
Safety requirements
Require:
BASELODGE_RUNTIME_ENV=development
explicit BASELODGE_DEVELOPMENT_USER_MODE=1
explicit development database URL
PostgreSQL only
protected production identity rejection
target identity must match the configured development DB
Refuse before connection if any guard fails.
Never log:
database credentials
plaintext password
password hash
User creation behavior
Create exactly one local email-auth user.
Use a development-only email that I choose.
Prompt securely for the password using getpass.
Hash the password using the same Werkzeug password hashing behavior BaseLodge uses.
Do not use or copy my production password/hash.
Set enough profile data so the account can enter the normal authenticated app without being forced through onboarding.
Required fields should include:
first name
last name
development-only email
rider type
pass type
skill level
home state
Set safe development defaults:
auth_provider="email"
profile_setup_complete / onboarding fields as required by current guards
push notifications disabled
email opt-ins disabled where appropriate
discoverability disabled
mark as seeded/test if an existing safe field supports that
Create no:
friends
trips
invitations
availability
SkiDays
equipment
push-device tokens
analytics events
MessageEventLog rows
MountainPageView rows
Duplicate handling
If the requested development email already exists:
do not create another user
report that clearly
do not silently reset the password unless an explicit reset mode is separately approved
Verification
After creation, verify:
exactly one intended user row exists
password hash is present
no plaintext password is stored
required profile fields are present
no unrelated tables gained rows
production remains untouched
Workflow
Flask may remain running, but the creator itself must not depend on Flask or import app.py.
Do not restart the workflow automatically.
Commit requirement
If code changes are required, commit them with the task ID.

Return
Report:
files changed
safety guards
exact fields set on the development user
whether account creation succeeded
verification that no unrelated rows were created
confirmation production untouched
confirmation no email/analytics/push/OneSignal action occurred
Flask Server status
BL-77 status
Git commit hash and exact commit message if committed
End with exactly one:
