==================================================
PERSONA MODEL
==================================================

Design SIX deterministic underlying personas.

------------------------------
1. EMPTY
------------------------------

Brand-new or nearly brand-new account.

Should support:

- onboarding
- empty Home
- empty Trips
- empty Friends
- no availability
- empty Wishlist
- no visited mountains
- empty notifications
- minimal profile

------------------------------
2. LIGHT
------------------------------

Approximately:

- 3–5 reciprocal friends
- 1 organized trip
- 1 participant trip
- 1 pass
- 1 availability range
- 1 Wishlist mountain
- limited equipment/profile data
- 1 notification

------------------------------
3. TYPICAL
------------------------------

Approximately:

- 10 reciprocal friends
- several trips
- organizer and participant roles
- Going and Interested
- pending trip invitation
- several Ideas
- several Happening entries
- normal social overlap
- several Wishlist mountains
- several availability ranges
- multiple notifications

------------------------------
4. HEAVY
------------------------------

This is a CRITICAL persona.

Use exactly:

- 25 reciprocal friends
- 15 trips

The 15 trips should deliberately cover meaningful combinations of:

- organizer
- participant
- Going
- Interested
- invited/pending
- upcoming
- current if supported
- historical/past
- public/private where relevant

Also include:

- substantial mountain overlap
- substantial Wishlist overlap
- substantial availability overlap
- multiple pass families
- maximum 15-item Wishlist
- populated visited mountains
- populated equipment
- complete profile
- dense notifications
- multiple availability ranges across months
- enough data to max out capped Home intelligence sections
- enough data to create +N summarized social states
- enough data to exercise pagination/progressive loading

Do NOT simply generate 25 unrelated friends.

Create meaningful overlap clusters so the UI contains realistic social intelligence.

Determine a deterministic structure where subsets of the 25 friends overlap on:

- the same mountain
- the same Wishlist mountain
- the same pass
- the same availability dates
- the same trip
- different combinations of those dimensions

Use the actual BaseLodge intelligence rules discovered in the application.

Do not violate privacy/authorization rules to manufacture these states.

------------------------------
5. EXTREME
------------------------------

Purpose-built MOBILE layout stress.

Use:

- long but valid first/last names
- long supported trip/location copy
- long mountain/resort/location names
- dense trip roster
- long planning content
- long URLs where rendered
- maximum visible badges
- multiple simultaneous sections
- mixed populated and empty subsections
- content likely to wrap
- narrow-mobile stress where useful

This does not need to represent a realistic average user.

It exists to expose design limits.

------------------------------
6. EDGE
------------------------------

Used to create deterministic conditional states such as:

- loading
- no results
- recoverable failure
- retry
- 403
- 404
- 500
- invalid invite
- expired invite
- validation errors
- terminal/read-only trip
- progressive-loading states
- concurrency conflict
- export failure
