Goal:
Replace the current Home next-trip presentation with a compact, information-dense “Your Next Trip” module that keeps the most useful trip information visible without consuming excessive vertical space.

PRODUCT CONTRACT

The module should include:

Header:
Your Next Trip

Upper-right action:
View trip >

Trip content:
- mountain/resort name
- trip date range
- number of nights
- number of friends going
- relative countdown such as:
  - Trip in 12 days
  - Trip tomorrow
  - Trip today

Example presentation:

Your Next Trip                    View trip >

Vail
Jan 13–17 · 4 nights
4 friends going · Trip in 12 days

This is an example of hierarchy, not hardcoded content.

Use actual trip data and existing canonical semantics.

- ownership boolean

- recalculate participant eligibility with new semantics
- introduce new trip visibility logic

DATE BEHAVIOR

Use the user-relevant effective trip dates already attached/resolved for Home.

Preserve:
- owner trip dates
- effective guest attendance dates
- in-progress trip behavior
- existing trip sorting/selection semantics

NIGHTS

- 1 night

FRIENDS GOING

4 friends going

Use existing authoritative participation/friend semantics already available to Home where possible.

Do not add N+1 queries.

If the required friends-going count cannot be produced safely from already-loaded/canonical data without a new query or semantic decision, STOP and report that specific issue rather than inventing behavior.

COUNTDOWN

Show a concise relative timing label based on the user-relevant effective start date.

Required states:
- future >1 day: “Trip in X days”
- tomorrow: “Trip tomorrow”
- today/in progress: “Trip today”

Do not add live JavaScript countdown behavior.
Server-rendered day-level precision is sufficient.

VIEW TRIP
