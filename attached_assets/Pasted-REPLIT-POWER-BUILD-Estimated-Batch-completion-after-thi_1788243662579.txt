TASK: BL-178 — Add structured request observability

Use Task #416 PLAN as the implementation contract.

GOAL

Add the smallest production-safe request observability layer for BaseLodge:

- opaque server-generated request IDs
- safe structured JSON events for unhandled errors
- safe structured JSON events for slow requests
- X-Request-ID on responses

Keep all existing browser/API behavior unchanged.

IMPLEMENT ONLY THIS SCOPE.

1. REQUEST CORRELATION

At the earliest centralized Flask request hook:

- generate a new cryptographically random opaque request ID
- ignore any inbound request-ID header
- store the ID in request-local context
- record a monotonic request start time

For every response, including:
- normal success
- redirects
- 404
- 500
- CSRF failures
- rate-limit 429 responses

return:

X-Request-ID: <server-generated-id>

The ID must contain no user, session, IP, route, timestamp, or business data.

Do not use process-global correlation state.

2. STRUCTURED OBSERVABILITY HELPER

Add one focused application helper/module for the new request-event family.

Emit newline-delimited JSON with an explicit allowlist only.

Required fields:

- timestamp
- severity
- event_type
- request_id
- method
- endpoint
- route
- status_code
- duration_ms
- environment

For error events only:
- exception_class

Optional:
- tightly bounded exception source location metadata if it can be captured without locals, values, request data, or exception message text

Use normalized Flask endpoint and route rule.

NEVER include:
- raw URL
- query string
- request body
- response body
- form data
- JSON payload
- headers
- cookies
- session data
- CSRF values
- reset tokens
- OAuth credentials
- push tokens
- authorization credentials
- email addresses
- IP addresses
- user IDs
- session IDs
- user-agent
- SQL parameters
- model objects
- provider payloads
- raw exception message/text

Do not serialize arbitrary dictionaries into these events.

3. UNHANDLED ERROR EVENT

Integrate with the existing centralized unhandled-error path.

For an unhandled application 5xx:

- emit exactly one structured error event
- use the same request ID returned to the caller
- include normalized route metadata
- include status and duration
- include exception class only, not its message
- preserve existing database rollback behavior
- preserve existing browser/API error response contract

Do not double-log the same exception through the new structured event path.

Existing unrelated free-form logging may remain unchanged unless a duplicate from the same new hook must be removed.

4. SLOW REQUEST EVENT

Add low-noise latency logging.

Use a conservative application-level threshold.

Requirements:

- use monotonic elapsed time
- emit only when response duration crosses the threshold
- use normalized route/endpoint
- include request ID and status
- do not log every successful request
- do not add sampling
- do not build route-specific timers

Choose one sensible default threshold from the PLAN/code context and centralize it so it can be changed later without touching route logic.

Do not turn this into BL-179 alerting.

5. RESPONSE CONTRACT PRESERVATION

Do not change:

- existing browser error pages
- API JSON bodies
- status codes
- redirects
- auth behavior
- session behavior
- CSRF behavior
- 429 bodies/headers
- Production debug settings
- provider/analytics failure semantics

The only new response contract should be X-Request-ID.

6. PRIVACY SAFETY

Add focused tests proving representative sensitive values cannot appear in structured request events.

Include representative examples for:
- email
- query-string secret
- request-body secret
- cookie/session value
- CSRF token
- reset/auth token
- push credential
- raw exception message

Preserve BL-201 deleted-account email protections.

7. RUNTIME MODEL

Keep the implementation safe for multiple Gunicorn workers.

Do not add:
- process-local aggregation
- file logging
- shared in-memory request registry
- database storage
- Redis
- external observability vendor
- new Production configuration

stdout/stderr structured events are sufficient for this task.

CRITICAL CONSTRAINTS

Preserve:
- BL-168 session hardening
- BL-169 CSRF
- BL-170 rate-limit behavior
- BL-201 sensitive logging protections

DO NOT:
- reformat all existing logs
- add access logging for every request
- add dashboards
- add alerts
- add Sentry/Datadog/Better Stack/etc.
- change Gunicorn configuration unless validation proves it is strictly necessary
- change schema/index/migrations
- change secrets
- deploy
- touch Production or persistent data

VALIDATION

Run focused tests only.

Cover:

- every request receives a new server-owned request ID
- request IDs differ across requests
- inbound X-Request-ID is ignored
- request ID is available during request handling
- X-Request-ID appears on success
- X-Request-ID appears on redirects
- X-Request-ID appears on 404
- X-Request-ID appears on 500
- X-Request-ID appears on CSRF failure
- X-Request-ID appears on 429

Structured error event:
- valid JSON
- exactly one event for an unhandled error
- required fields present
- normalized route used
- exception class present
- raw exception message absent

Slow event:
- below-threshold request emits nothing
- above-threshold request emits one event
- correct request ID/status/route/duration
- no retries or secondary logging side effects

Privacy:
- representative sensitive values are absent from captured structured events

Compatibility:
- existing browser 500 behavior unchanged
- existing API error JSON unchanged
- auth redirect behavior unchanged
- CSRF behavior unchanged
- 429 body/header behavior unchanged

Also run:

- git diff --check
