BASELODGE — #239 ADD CSRF TO HIGH-PRIORITY HTML FORM MUTATIONS

Implement ONLY coordinated CSRF protection for the high-priority HTML form routes listed below.

Audit #234 confirmed these routes are browser/session-authenticated mutations that currently lack complete CSRF protection.

Unlike the fetch/API routes, these require BOTH:

1. hidden csrf_token input in the form
2. validate_csrf_request() in the receiving handler

DO NOT:
- modify global CSRF infrastructure
- modify the fetch wrapper
- change authentication
- change permissions
- change notifications
- change business logic
- change schema
- redesign forms
- touch unrelated routes

==================================================
1. ROUTES IN SCOPE
==================================================

Protect these form-based routes:

POST /add_trip

POST /trips/<id>/invite

POST /trips/<id>/invite/cancel

POST /trips/<id>/request-join

POST /trips/requests/<id>/respond

POST /trips/requests/<id>/cancel

POST /trips/<id>/respond

POST /trip-invite/<token>/accept

POST /connect/<id>/add

If exact route names/parameter names differ, use the current definitions.

NOTE:

The legacy /trips/<id>/edit form has already been retired.
Do NOT resurrect or modify it.

==================================================
2. TRACE EACH FORM FIRST
==================================================

Before editing each route:

Identify the exact template/form or JS-generated FormData caller.

Confirm:

- method is POST
- action/endpoint
- whether csrf_token already exists
- whether validate_csrf_request() already exists
- whether the submission is a normal HTML form or fetch-based

If a route already has full protection:
do not duplicate it.

If a supposed form route is actually fetch-only and already receives X-CSRF-Token:
report that and add backend validation only if appropriate.

==================================================
3. HTML FORM PATTERN
==================================================

For each true HTML POST form missing a token, add:

<input type="hidden" name="csrf_token" value="{{ csrf_token() }}">

Place it directly inside the relevant <form>.

Use existing BaseLodge pattern.

Do not alter layout or visible copy.

==================================================
4. BACKEND VALIDATION
==================================================

For each in-scope handler that does not already validate CSRF, add:

validate_csrf_request()

before:

- payload/form parsing
- DB mutation
- participant/invite changes
- friendship creation
- notification dispatch

Preserve all existing auth and permission checks.
