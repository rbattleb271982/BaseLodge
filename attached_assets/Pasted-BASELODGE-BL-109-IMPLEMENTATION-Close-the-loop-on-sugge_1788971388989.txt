CONVERSION RULE
==================================================

Implement a deterministic, non-causal conversion rule.

For a FriendSuggestion S:

1. Canonicalize the suggested pair:

   pair_a = min(S.recipient_id, S.suggested_user_id)
   pair_b = max(S.recipient_id, S.suggested_user_id)

2. The pair must NOT already have been connected when S was created.

Use FriendConnectionEvent lifecycle history to determine the pair's state immediately before/at the suggestion.

A suggestion created while the pair was already connected must not qualify.

3. Find the earliest `formed` FriendConnectionEvent for the canonical pair occurring AFTER S.created_at.

4. Attribute S only to that formation event.

5. Collapse matches by:

   - suggester_id
   - canonical pair
   - formation event ID

Repeated suggestion rows from the same introducer for the same formation event must produce only one Happening card.

6. Multiple independent suggesters may each receive their own card.

7. Old suggestions must not produce new confirmation cards for later reconnection cycles.

8. A NEW suggestion made after a removal, while the pair is disconnected, may qualify for the later reconnection.

Be explicit and deterministic at timestamp boundaries.

If existing project conventions establish timestamp tie-breaking behavior, follow them and cover the behavior with tests.
