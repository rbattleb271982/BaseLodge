Approved implementation
Only if the deployed schema matches expectations, make these five cleanup changes.
1. Invitations tied to owned trips
Before deleting the signed-in user's owned trips:
collect the owned trip IDs
hard-delete Invitation rows whose trip_id belongs to those trips
This includes invitations where the sender and receiver are both other users, because the underlying trip itself is being deleted.
Do not delete invitations associated with surviving trips unless existing account-deletion behavior already requires their deletion.
2. FriendCooldown
Delete FriendCooldown rows where the deleting user is either:
user_a_id
user_b_id
3. FriendSuggestion
Delete FriendSuggestion rows where the deleting user is:
suggester_id
recipient_id
suggested_user_id
4. SuggestionPushCooldown
Delete SuggestionPushCooldown rows where the deleting user is either:
suggester_id
recipient_id
This is pair-specific delivery-throttling state only.
Do not change any other push-notification behavior.
5. Activity records for deleted owned trips
Before deleting owned trips, delete Activity rows whose existing object_type / object_id semantics identify one of those owned trips.
This prevents stale Activity records pointing to trips that no longer exist.
Do not apply this behavior to MessageEventLog. Those audit records must remain preserved.
Preserve existing behavior exactly
