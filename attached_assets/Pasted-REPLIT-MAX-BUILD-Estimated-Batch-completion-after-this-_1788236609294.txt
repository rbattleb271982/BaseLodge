TASK: BL-172 — Replace Trip Detail mutation reloads with targeted UI updates

Use Task #413 PLAN as the implementation contract.

IMPLEMENT ONLY THE APPROVED SCOPE.

GOAL

Replace avoidable Trip Detail full-page reloads with targeted canonical region refreshes while preserving all existing product behavior, authorization, notifications, CSRF, rate limits, paging, and native behavior.

IMPLEMENT

1. Add stable server-rendered region markers for only the needed Trip Detail regions:
   - summary/location
   - Stay
   - People / join requests
   - participant setup
   - invite controls
   - lifecycle/organizer controls where required

2. Add one small shared targeted-refresh helper that:
   - fetches canonical Trip Detail HTML
   - extracts only requested regions
   - replaces those regions
   - preserves current scroll position
   - prevents stale/late responses from overwriting newer state
   - does not automatically retry failed requests or 429s
   - falls back to normal navigation if the result is no longer safely applicable to the current Trip Detail page

3. Convert these safe same-page mutations:
   - resort change
   - Stay save
   - Stay clear
   - join-request approve/decline
   - invite send
   - invite cancel
   - invite resend
   - same-page RSVP changes
   - organizer participant status/remove actions that retain current-page access

4. Disable the initiating control while its mutation is pending and restore it appropriately after completion/failure.

5. RETAIN NORMAL NAVIGATION for:
   - delete/cancel trip
   - leave trip
   - complete trip
   - access-ending actions
   - any server response or redirect whose destination is not the current Trip Detail page

6. Preserve existing actions that already update locally unless a narrowly required canonical region refresh is needed to prevent stale derived content.

CRITICAL CONSTRAINTS

- Reuse existing mutation routes.
- Server remains source of truth.
- Do not duplicate RSVP, invitation, lifecycle, authorization, or visibility rules in JavaScript.
- Do not introduce a client-side state store.
- Do not introduce React/Vue/framework changes.
- Do not change product copy or redesign Trip Detail.
- Do not change notification semantics or deduplication.
- Do not change BL-133 visibility behavior.
- Do not change BL-158/159 paging behavior.
- Preserve BL-168 auth/session behavior.
- Preserve BL-169 CSRF behavior.
- Preserve BL-170 rate limits and 429 handling.
- Do not add schema/index/migration changes.
- Do not touch Production or persistent data.
