BASELODGE — MY SETUP SAVE BEHAVIOR AUDIT + FIX

Use Economy.

Investigate and fix the interaction behavior for the personal “My Setup” controls on trip_detail:

- Pass
- Equipment
- Lessons

Current UX problem:

These controls are editable directly on the normal trip page, but after selecting a value there is no clear Save action or confirmation. I cannot tell whether my selection actually persisted.

Desired behavior:

MY SETUP is always directly editable for the current user.

Each field should SAVE IMMEDIATELY when a selection is made.

There should NOT be a global Save button for My Setup.

==================================================
1. FIRST VERIFY CURRENT BEHAVIOR
==================================================

Before changing code, trace and test each control:

PASS
- What JS fires after selecting a pass?
- What endpoint is called?
- Does it successfully save SkiTripParticipant.pass_type?
- Does the displayed row update?
- Does the bottom sheet close?
- Does the value survive page reload?

EQUIPMENT
- What JS fires after selecting an equipment option?
- Does it call participant/signals?
- Does SkiTripParticipant.equipment_status update?
- Does the row value update?
- Does the accordion close?
- Does the value survive reload?

LESSONS
- What JS fires after selecting:
  - No lesson
  - Taking a lesson
  - Considering a lesson
- Does it call participant/signals?
- Does SkiTripParticipant.taking_lesson update?
- Does the row value update?
- Does the accordion close?
- Does the value survive reload?

Identify whether the issue is:

A. data is saving but UX gives no confirmation

or

B. data is not actually saving

Do not guess.

==================================================
2. REQUIRED FINAL BEHAVIOR
==================================================

For all three My Setup fields:

User selects a value
→ AJAX request fires immediately
→ server validates and saves
→ row summary updates
→ selector closes after successful save
→ user gets lightweight confirmation

No global Save button.

No dependency on owner Edit mode.

==================================================
3. PASS
==================================================

On successful Pass selection:

- save immediately using the existing participant-scoped pass endpoint
- update the Pass row text
- close the pass bottom sheet
- show a lightweight success confirmation

Example toast:

Saved

Do not change Pass ownership.

Pass remains personal to current user.

==================================================
4. EQUIPMENT
==================================================

On successful Equipment selection:

- save immediately through the existing participant-scoped endpoint
- update row summary
- update “From profile” / “For this trip” subtext correctly
- collapse the Equipment accordion after successful save
- show lightweight “Saved” confirmation

If save fails:
- keep accordion open
- preserve previous committed value
- show error
- do not pretend save succeeded

- keep editor open

- show error
