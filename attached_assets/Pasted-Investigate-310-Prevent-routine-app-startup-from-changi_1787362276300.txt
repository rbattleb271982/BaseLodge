Investigate #310 — Prevent routine app startup from changing the database.
INVESTIGATION ONLY. DO NOT IMPLEMENT YET.
Context
BaseLodge development and production database isolation is now working correctly.
Production has safely advanced from:
bl60_mtn_filter_edu → bl305_ski_day_foundation

The immediate production ski_day outage has been resolved and manually verified in the live app.
However, normal application startup still executes numerous legacy database DDL/DML routines. We have already observed these routines running during development reloads and production cold starts, including push-token cleanup behavior.
The goal of #310 is to determine how to make normal BaseLodge application startup read-only with respect to schema/data maintenance, while preserving everything the application legitimately needs to boot.
