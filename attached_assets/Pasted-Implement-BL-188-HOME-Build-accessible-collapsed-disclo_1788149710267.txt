IMPLEMENTATION CONTRACT

1. Create reusable Home disclosure macro

Create:

templates/macros/home_disclosure.html

Use a Jinja caller macro.

Required inputs:

- disclosure_id
- title
- summary

Optional inputs only if genuinely useful:

- class_name
- content_class

The macro must own:

- <details>
- <summary>
- visible title
- collapsed summary
- decorative chevron
- stable derived IDs
- expanded labelled content region
- reusable structural classes

The caller body owns only expanded module-specific content.

ID contract:

details:
<disclosure_id>

title:
<disclosure_id>-title

panel:
<disclosure_id>-panel

Expanded panel must use:

role="region"
aria-labelledby="<disclosure_id>-title"

Do not introduce domain logic into the macro.

2. Native accessibility behavior

Render <details> WITHOUT the open attribute.

Use direct-child <summary> as the only control.

Do NOT add:

- role="button"
- tabindex
- manually managed aria-expanded
- manually managed aria-controls
- custom click handlers
- key handlers
- disclosure initialization JavaScript

Native details/summary semantics should provide expanded/collapsed state and keyboard interaction.

Preserve native Enter and Space activation.

Do not move focus when toggled.

3. Full-row mobile interaction

The complete <summary> row must be the interactive target.

Requirements:

- full width
- minimum 44px interactive height
- visible :focus-visible treatment
- mobile/touch appropriate
- long title and summary must wrap
- no text clipping
- no nowrap
- no ellipsis
- no fixed-height copy container

Do not create a separate chevron button.

4. Layout

Use the approved compact Home disclosure structure.

Header shell may use:

grid-template-columns: minmax(0, 1fr) auto

This grid is ONLY for:

- text area
- decorative chevron

Expanded content remains single-column.

Within the text area:

- title stacked above collapsed summary
- title always visible
- collapsed summary visible only while closed

Do not force title + summary inline.

Do not create two-column value/content layouts.

5. Visual treatment

Keep styling Home-scoped and consistent with existing BaseLodge Home surfaces.

Use:

- compact spacing
- white rounded card where consistent with current Home
- inherited typography
- relative line height
- natural vertical growth
- restrained gaps

Do not perform a broader Home redesign.

Absolutely do not add:

- photographs
- image placeholders
- thumbnails
- profile bubbles
- avatars
- decorative mountain illustrations

6. Chevron

Reuse existing BaseLodge visual conventions where practical.

Chevron must be:

- decorative
- non-focusable
- not separately clickable
- rotated only based on details open state

Use CSS or an aria-hidden/focusable-false element.

A short transform transition is acceptable.

If transition exists, add:

@media (prefers-reduced-motion: reduce)

and disable that transition.

Do not animate expanded content height.

7. Expansion behavior

Expansion/collapse must use normal document flow.

Do not:

- scrollIntoView
- force-scroll
- manually preserve offsets
- re-render Home
- animate content height
- use max-height animation
- create localStorage/sessionStorage/cookie/session persistence

State remains browser-native and client-only.

Fresh page render starts collapsed.

Browser back/forward behavior may remain whatever the browser naturally provides.
