OBJECTIVE

Add filtering to the existing Friends list so users can narrow friends by:

- ski pass
- rider type
- skill level

while continuing to use the existing “Search friends” behavior.

The intended UX is:

1. Existing Search friends field remains.
2. A compact **Filter** control appears directly below search.
3. Tapping Filter opens a bottom sheet.
4. Bottom sheet contains three multi-select sections:
   - Pass
   - Rider type
   - Skill level
5. Active filters appear as removable chips beneath the search/filter controls.
6. Filter button shows active-filter count, e.g. `Filter (3)`.
7. Search and filters work together.
8. Existing alphabetical friend grouping remains correct.
9. Existing friend-row design, Invite flow, navigation, and profile behavior remain unchanged.

## 3. Filter semantics
Use these rules unless current data constraints require an adjustment:

### Within one category
Multiple selections are OR logic.

Example:
`Ikon + Epic`
means friends with either Ikon OR Epic.

### Across categories
Different categories are AND logic.

Example:
`Ikon + Advanced`
means friends who match an Ikon filter AND Advanced skill level.

### Search
Text search should combine with active filters.

Example:
search = `Bry`
filters = `Ikon + Expert`

Only friends matching both the search term and filter conditions should remain.
