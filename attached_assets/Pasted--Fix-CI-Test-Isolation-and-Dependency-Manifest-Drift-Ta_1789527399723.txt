### Failure 1 — PostgreSQL test isolation

The mandatory PostgreSQL gate ran:

tests/test_bl443_cutover_postgres.py
tests/test_connection_transitions_postgres.py

in the same pytest process.

Result:

29 passed
4 failed
0 skipped

The four connection-transition tests fail before exercising concurrency behavior with:

psycopg2.errors.UndefinedColumn:
column "first_name" of relation "user" does not exist

Task #561 established that this is NOT a schema or migration defect.

The root cause is a process-global test isolation leak.

In:

tests/test_bl443_cutover_postgres.py

the test:

test_full_path_production_settings_resources_and_preflight_postgres

calls create_worker_resources().

That worker setup intentionally replaces:

db.session

with its own scoped worker session.

The BL-443 test removes the worker session and disposes its engine during teardown but does not restore the original Flask-SQLAlchemy db.session object.

Because the later connection-transition module executes in the same pytest process, its db.create_all() correctly creates a full schema in its own disposable PostgreSQL database, but _make_user() subsequently resolves the stale BL-443 worker session and writes to BL-443's intentionally partial database containing only user(id).

The correct fix is to restore the original db.session after the BL-443 worker test.

Do not expand the BL-443 partial schema to hide the leak.

### Failure 2 — Source integrity dependency drift

The Source integrity job runs:

FAIL: runtime dependency manifests differ

Task #561 established:

requirements.txt contains:
- freezegun

pyproject.toml does not.

Both packages have real repository imports in capture functionality.

This mismatch predates the PostgreSQL work.

The correct fix is to add the missing runtime dependencies to pyproject.toml and regenerate uv.lock so the dependency manifests agree.

No application migration is required.
