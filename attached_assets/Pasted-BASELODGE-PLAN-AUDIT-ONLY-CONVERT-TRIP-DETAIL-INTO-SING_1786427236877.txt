BASELODGE — PLAN/AUDIT ONLY
CONVERT TRIP DETAIL INTO SINGLE-PAGE OWNER EDIT MODE

DO NOT IMPLEMENT YET.

I want to simplify the trip-owner experience so there is ONE primary trip page instead of:

1. trip detail page
2. separate Edit Trip page
3. additional inline editors

The desired product direction is:

NORMAL TRIP VIEW
- Trip summary
- My setup
- Trip planning
- Invite friends
- People
- Cancel trip

OWNER TAPS EDIT
- The SAME trip detail page enters edit mode
- Mountain/location becomes editable
- Dates become editable
- Visibility becomes editable
- Planning / Going becomes editable
- Private note appears and becomes editable
- My setup remains editable
- Edit changes to Done / Save or another appropriate completion action
- Owner stays on the same trip page

ACCEPTED PARTICIPANT
- Does NOT see owner Edit control
- Cannot edit trip-level fields
- Can still edit THEIR OWN personal setup:
  - Pass
  - Equipment
  - Lessons
- Can access Trip Planning
- Never sees Private note

The separate /trips/<id>/edit page should eventually no longer be part of the user-facing journey once the single-page experience is stable.

For now this task is ONLY an audit and implementation plan.

PERSONAL / CURRENT USER

Equipment is personal.

Lessons is personal.

Audit whether the current data model actually supports this intended ownership cleanly.

- partial failures
- mobile UX
