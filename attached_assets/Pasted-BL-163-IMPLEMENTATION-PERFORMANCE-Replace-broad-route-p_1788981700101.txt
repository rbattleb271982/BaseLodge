APPROVED BL-163 PRODUCT / TECHNICAL CONTRACT
--------------------------------------------------

Replace broad page-load route speculation with conservative user-intent prefetching.

BaseLodge must NOT broadly prefetch routes or APIs merely because an authenticated page loaded.

Approved prefetch destinations for this task are ONLY:

- /home
- /my-trips
- /friends
- /mountains
- /profile

Do not broaden this allowlist.

Explicitly DO NOT prefetch:

- /api/mountains-data
- any /api/* route
- Trip Detail
- Mountain Detail
- friend/user detail pages
- /edit-profile
- /settings/equipment
- auth routes
- logout
- invite/token/action URLs
- account-state routes
- admin/diagnostic/health routes
- downloads
- external origins
- mailto:
- tel:
- sms:
- fragments
- target="_blank" links
- JavaScript-only controls
- any destination not explicitly in the five-path allowlist

Normal navigation must remain unchanged.

--------------------------------------------------
3. INTENT SIGNALS
--------------------------------------------------

Use delegated document-level handling for:

- pointerenter
- focusin
- pointerdown

Purpose:

pointerenter:
desktop mouse/stylus intent

focusin:
keyboard accessibility

pointerdown:
touch/mobile intent and direct pointer commitment

Do NOT use:

- IntersectionObserver
- viewport-based prefetch
- page-load prefetch
- timers
- predictive scoring
- route popularity
- mouse movement prediction
- background route warming

Initialization itself must create ZERO prefetch hints.

--------------------------------------------------
4. ELIGIBLE LINK RESOLUTION
--------------------------------------------------

For an intent event:

1. Find the relevant nearest anchor for the event target.
2. Ignore the event if there is no eligible anchor.
3. Resolve the anchor URL safely against the current document.
4. Require same-origin.
5. Require pathname to be EXACTLY one of:

   /home
   /my-trips
   /friends
   /mountains
   /profile

6. Ignore the current page destination.
7. Reject links with unsafe/ineligible attributes or schemes.
8. Preserve ordinary query strings only if the underlying destination remains safely equivalent.

Be conservative.

If query/hash handling introduces ambiguity, reject the prefetch rather than broadening eligibility.

Do not allow prefix matching such as:

/friends/*
/profile/*
/mountains/*

Eligibility is exact-path only.

--------------------------------------------------
5. LINK SAFETY
--------------------------------------------------

The intent system must reject at minimum:

- cross-origin URLs
- non-http(s) schemes
- fragments / hash-only navigation
- mailto:
- tel:
- sms:
- download links
- target="_blank"
- links outside the five approved paths

Do not create a generic blacklist of BaseLodge routes.

The exact allowlist is the primary safety boundary.

--------------------------------------------------
6. DEDUPLICATION
--------------------------------------------------

Maintain one document-lifetime Set of normalized eligible destinations.

A destination must be added to the Set before its prefetch hint is appended.

Multiple events for the same normalized destination must create at most ONE prefetch hint.

Examples:

pointerenter → focusin
pointerenter → pointerdown
repeated pointerenter

must not create duplicate hints.

Do not create persistent storage, session storage, local storage, or cross-page state for this.

--------------------------------------------------
7. PREFETCH MECHANISM
--------------------------------------------------

For an eligible destination after actual user intent:

create one:

<link rel="prefetch">

for the normalized destination.

Use the browser's native low-priority prefetch behavior.

Do NOT replace this with:

fetch()

Do NOT:
- consume response bodies
- implement a custom response cache
- add AbortController
- intercept click
- call preventDefault()
- delay navigation
- turn navigation into SPA behavior

Ordinary anchor navigation remains the fallback and source of truth.
