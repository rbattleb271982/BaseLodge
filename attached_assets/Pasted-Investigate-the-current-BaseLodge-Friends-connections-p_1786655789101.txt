Investigate the current BaseLodge Friends, connections, profile settings, privacy, and notifications architecture and determine exactly what would be required to let users search for other registered BaseLodge members by name and send them a connection request from the existing Friends screen.

This is an investigation only.

Do not change any code, models, database schema, migrations, templates, styles, JavaScript, routes, services, tests, configuration, or settings.

Do not commit, push, publish, or deploy anything.

Product behavior we are considering

BaseLodge already has a Friends screen with:

* Header: Friends
* Invite action
* Existing Search friends field
* Alphabetical list of current friends
* Friend rows containing richer information such as:
    * Name
    * Skier / snowboarder
    * Ability
    * Passes
    * Upcoming trip count

We want to investigate extending this existing experience so users can also find people who have already signed up for BaseLodge.

Proposed search experience

The existing Search friends field would potentially do both:

1. Search/filter the user’s existing friends
2. Search eligible registered BaseLodge users who are not already friends

Do not search by email.

Search should be based on the person’s name.

For a registered BaseLodge member who is not currently a friend, the result should be intentionally minimal.

Proposed format:

John Smith · Colorado         Connect
4 mutual friends

Another state:

John Smith · California     Connect
2 mutual friends

Pending outgoing request:

John Smith · Colorado     Requested
4 mutual friends

The purpose of showing home state is to help distinguish people with identical or similar names.

The purpose of showing mutual friends is to provide additional social context so the user can identify the correct person.

Do not assume this exact UI implementation is technically correct yet. Investigate what the existing architecture supports and recommend the smallest clean implementation.
